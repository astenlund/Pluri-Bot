# Mechanical game-notes validation before session end

Paths under `development/` in this file name the frozen local archive in the LocalAppData folder the project came from; they are not part of this repository.

The game-notes finalize step validates `target_display.<display>.last_checked` with `^\d{4}-\d{2}-\d{2}T` plus `DateTimeOffset.TryParse` (RoundtripKind), so it requires a date and time. The mission text only says "Use an ISO 8601 last_checked value or leave it empty", and a bare date such as `2026-11-06` satisfies that wording. An agent that follows the prose can therefore write notes that pass its own strict-grammar checks but fail at exit, when no agent is left to repair them. The agent and the finalize step judge the same file by different rules; sharing one validator removes that drift for every target-display rule, not only this timestamp.

Observed 2026-11-06 in RESIDENT EVIL 7 biohazard (v54): the session ended with "WARNING: Could not finalize game notes: Target display timestamp is invalid: target_display.lg-ultrawide.last_checked" and exit code 5. Installed files and verification were unaffected; a resumed session repaired the value by hand.

Still present in v62: the finalize step reads the target store and runs each post-run check `PROJECT.json` declares, and the `display-targets` check raises the same timestamp error, which the session end reports as "Could not finalize game notes" with exit 5; the mission wording is unchanged.

Proposal:

- Add a read-only internal command, for example `--internal-notes-validate`, that runs exactly what the session end runs over the target store: the store read, then each post-run check the mission declares, so the agent's check and the session end cannot drift and the command serves any mission, not only DLSS. It takes no path: the running copy names its own location, as `--internal-location-set` and `--internal-hardware-probe` do, so it cannot be pointed at an arbitrary file.
- The command reports one of three outcomes as one compact JSON line, mirroring the session end's distinction: pass; finding (an incomplete selection, which the session end records as `display_selection_pending` with exit 4 and which is legitimate mid-session), with the finding text; or damage (a malformed record or unreadable store, which the session end reports with exit 5), with the exact error. Exit codes follow the existing internal commands: 0 for a report of any outcome, 2 for invalid usage, 4 for an inspection failure.
- Mission: require running it after every game-notes write and before the final completion report. Damage must be repaired before continuing; at the completion report, any finding must match what the agent reports.
- Mission wording: change the last_checked rule to "an ISO 8601 date and time with offset, for example 2026-11-06T23:17:27+01:00, or empty".
- Keep the validator strict; do not widen it to accept bare dates.
- Tests: release-suite cases for the command (valid notes; date-only last_checked; another target-display domain error; an incomplete selection reported as a finding; a mission that declares no post-run check) and a generated-prompt assertion for the new requirement and wording.
- It changes no host launch behavior, so the release carries the previous release's live host probe records forward.

Resolved 2026-11-16: the [Composable AI bootstrap builder](composable-bootstrap-builder.md) Stores slice shipped in v57 without absorbing this fix (it made the display check the built-in `display-targets` post-run check), so this lands as a standalone release. Captured 2026-11-06.

Shipped 2026-11-17 in bootstrap v64 (gist revision 6a638d37187701f17ee44a24944e4426194be4c5, SHA-256 b0c326d2e510f0dae457858df6d942e4ea9d42c9f38d675836efe68a62450429). What shipped differs from the proposal above in these points: the command is `--internal-notes-validate`; the trusted game-local copy accepts it and the shared AppData copy refuses it with exit 2; for a mission other than `dlss5` it runs that mission's own default session end check, the free-form store check `Assert-Dlss5MissionStoresAfterSession`, rather than the game notes read, so it serves any mission by running what that mission's session end runs; any character outside ASCII in its JSON line is escaped; and the `last_checked` rule reads "an ISO 8601 date and time with offset in the extended form of 2026-11-06T23:17:27+01:00, or leave it empty", since the validator needs the extended `YYYY-MM-DDT` date part. The mission makes damage a repair in every session, and makes a finding binding only in a default session, since a task or diagnosis-only session's end runs no display check. The validator stays strict and unchanged, so a date and time without an offset still passes. The release suite gains two cases in `tests\Test-DLSS5MissionStores.ps1` and generated-prompt assertions in `tests\Test-DLSS5Adder.ps1`. Minor findings deferred from its review are tracked in [the v64 review minors bug](../bugs/v64-notes-validation-review-minors.md). Release records in `development/v64-notes-validate/`.
