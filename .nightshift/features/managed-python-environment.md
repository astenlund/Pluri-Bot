# Managed Python environment for local runtime patching

When local patching needs Python and no suitable interpreter is available, offer to acquire a pinned, verified private Python runtime in the AppData store and create a dedicated venv for dependency tooling. Reuse the environment across builds and invoke its executables by absolute path without activation or PATH changes. Preserve explicit user approval before acquiring Python or other software. The current patcher uses the standard library; CUDA tool wheels remain downloaded and extracted rather than requiring a CUDA Toolkit install. Captured 2026-10-21.

## Decisions (v47)

- **Selection:** an existing interpreter keeps precedence when it reports 3.10 or newer, is 64-bit and has a working pip; the managed runtime is used or offered only when none qualifies, and an interpreter inside the store never counts as existing.
- **Distribution:** the official python.org NuGet package (package ID python on nuget.org). It includes venv and pip, needs no installer, registry or PATH change, and its executables and Python DLLs are signed by Python Software Foundation. The embeddable zip was ruled out because it has no venv or pip.
- **Integrity:** at acquisition, the package's SHA-512 must equal the nuget.org catalog packageHash, and python.exe, pythonw.exe and every python*.dll need a Valid Python Software Foundation signature and the offered version. Before each use, .pyc files in bytecode caches are cleared, every installed runtime file must match the kept .nupkg, whose SHA-256 must match the pin, with no extra files, and the signatures and version are rechecked; repair refetches the recorded version and requires the recorded package SHA-256. The venv is checked before each use (signatures, version, pyvenv.cfg, and a pip byte-identical to the runtime's) and recreated only when absent or failing. The patcher and pip run with -I and -B.
- **Pin ownership:** the user's acceptance is recorded per machine in dlssnr_patcher.python as version@package-SHA-256; the bootstrap ships no trusted Python version.
- **Repair, updates and cleanup:** a failing runtime is replaced as repair without confirmation, except that a file the checks neither expect nor allow blocks automatic repair until the user confirms its removal, and an existing runtime folder found at acquisition is kept only if it passes the checks; the pin is recorded only after the runtime and venv pass; staging folders carry a random suffix so concurrent sessions cannot share one; a newer stable version is offered once per session that uses the runtime and re-pins only on acceptance, while a postpone or a failed update keeps the recorded runtime in use; removing a runtime or venv folder needs exact-target confirmation and removing the recorded runtime empties the pin.

The managed runtime was built as v47 and published on 2026-10-24.
