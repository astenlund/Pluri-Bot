# Mistral Vibe host

Support Mistral Vibe as a third AI host beside Claude Code and Codex CLI, selectable wherever those are (host detection, the interactive choice, `--host`, `--model`, `DLSS5_AGENT_HOST` and the per-host model and effort settings). Connected to [Offer AI host install](offer-ai-host-install.md), which would then cover it as an install candidate, and to [Non-interactive mode](non-interactive-mode.md), which would need Vibe's nearest equivalent of a no-prompt permission mode. Open questions: whether Vibe accepts an initial operating prompt and launches interactively the way the current hosts do (Nightshift found that its configuration can replace or trim Vibe's own system prompt through `system_prompt_id` and the `include_` settings), how its permission and approval modes map to the operating rules, how model and effort selection map to Vibe given that, as of Vibe 3.0.0, its command line has no model option (its configuration pins the model through `active_model` and sets each model's `thinking` level), whether it can read the situational instruction files the prompt names, how the release suite exercises a third host, and whether the models it runs are good enough for the game-session rules. Nightshift has already explored running Vibe non-interactively; check there before starting implementation: the "Admit Mistral Vibe and GLM as a reviewer host" entry in `C:/Git/nightshift/.nightshift/FEATURES.md`, the launcher `tools/seeded-defects/vibe-launcher.js`, and the reports under `.nightshift/reports/` (the GLM review evaluation and the seeded-defect baseline).
