## Entries

- **Shorten the release suite runs (2026-11-09).** Landed after v57 as release tooling, shipping no bootstrap change; a later release is the first to use it. `tests\Test-DLSS5Adder.ps1` now prints a `TIME` line per case and the slowest as `SLOW` lines, takes a test file filter (`DLSS5_TEST_FILE_FILTER`) beside the case filter, and fails when a filter selects nothing. In `development/v57-stores/`, `Invoke-BaselineSuite.ps1` replaces the baseline half of `Run-Both-Suites.ps1` by carrying results forward, `Invoke-PostReviewChecks.ps1` runs the full checks once on the reviewed bytes, `Invoke-FilteredSuite.ps1` runs selected cases on the off-screen runner, and `Test-BaselineSuite.ps1` covers the carry rules and these scripts with fixtures and stubbed runners. The Publication section of `AGENTS.md` describes the new order. Negative knowledge: the entry first proposed rerunning only the cases of a test file that changed, but that is unsafe on its own, because the test files share helpers (most of the other test files call functions defined in `Test-DLSS5Package.ps1`, and the files also call helpers defined in `Test-DLSS5Adder.ps1`). The carry rule therefore keeps a whole-file hash for each test file and one shared hash of all the files' text without their cases, the helper scripts, the historical packages the tests read and the suite runner scripts: a file whose whole-file hash changes while the shared hash does not, as with a change inside its cases, reruns alone if it has recorded results and still declares a case, is carried if it has none and a recorded guard stopped it, and otherwise forces a full run, and any change to the shared hash reruns everything. Three cases read the release folder's hello-world base rather than the baseline, so a rebuilt base has to rerun them; they are found in the test text, so a new reader needs no list kept. Cases whose assertions depend on what this machine's probes or live files return are marked by a `# live-input` comment and rerun every time. Machine tools and environment such as Git, `pwsh` and `PATH` are deliberately outside what the carry tracks: a stale carry can only skew the comparison against the old release, because the new code still runs every case each release. A release's post-review candidate run and the next release's baseline test the same bytes, so a passing post-review run is saved as `candidate-results.json` and the next `Invoke-BaselineSuite.ps1` starts from any sibling release folder's record of its baseline's exact hash, which avoids the full baseline run from the release after the first to record one, unless the carry rules require it. Parallel suite runs stay out of scope: `Invoke-SuiteOffscreen.ps1` allows one runner because it switches the per-user console host for the run.
